# v2.0 实施计划（顺序执行）

本计划是完整研究工程的阶段门槛，当前执行范围是仓库审计、契约、G0 接入与本地/远端预检。需要费用的训练以预算审批为界。细化的 G0 工程规格见 `openspec/changes/world-model-v2-g0/`。

## 0. 基线与仓库保护

1. 核验唯一仓库、Remote、工作树，复用 `feat/world-model-v2`，保留旧实现与负结果。
2. 建立 CodeGraph 与改造前运行架构图；保存审计、研究契约和本计划。
3. 创建仓库本地 `.venv`，修复测试依赖声明，运行现有单元测试与阈值 CLI。

## G0. 官方 Push-T 基线

1. 锁定官方 `le-wm` SHA、MIT 归因、论文版本、配置、数据仓库修订；上游代码保持外部来源，所有本地适配写明 patch/差异。
2. 写只读预检：校验上游身份、配置关键字段、训练数据存在与哈希、GPU/磁盘/环境、路径、预算上限；失败返回非零并保存诊断。
3. 在 AutoDL 核实可用 SSH、GPU、CUDA/PyTorch、磁盘与持久策略，检查运行进程，确认不会重复训练。
4. 解决官方当前 `.lance` 配置与公开 `.h5.zst` 分发的不一致，并在实际 Hydra 组合配置中复核 `wandb.enabled=False`；以真实数据加载测试而非猜测解决。
5. 给出小规模计时试跑及总预算。获批准后执行完整官方 Push-T 训练，再做独立加载与评测；保存配置、日志、参数变化、Checkpoint 与哈希。差异单列。

## G1–G6. 后续独立实施变更

- **G1**：冻结数据及 probe 拆分；按相同输入比较训练 LeWM 与预训练视觉特征，做 SIGReg/冻结消融和物理 probe。先通过 G0。
- **G2**：建立带完整状态快照、回放校验的 MuJoCo 接触场景；建立动作注入和事件预测模型、匹配对照与反事实评分。
- **G3**：先审计 ManiSkill-ViTac2025 许可、数据字段、同步和 SAPIEN 接口，再建立多模态数据契约与训练/消融。
- **G4**：在已验证数据上训练轻量生成式模型；独立评估帧质量、轨迹与事件一致性。
- **G5**：冻结 OOD 分组，执行模型规划与真实闭环环境对照；严格隔离 Oracle。
- **G6**：整合独立 benchmark 与最终五份报告；图表只来自已签名的实验工件。

每关另建 OpenSpec change、测试、运行收据和成本上限。模块随真实功能逐步落地；不创建空的 `models/`、`training/`、`planning/` 目录充当完成度。

## 当前阻塞

- `autodl-p1` 配置的 SSH 端点连接被拒绝；尚未核实实际 GPU 机器或价格。
- 官方当前 Push-T `.lance` 配置与公开 `.h5.zst` 数据不一致；上游已有通用转换接口，但具体数据转换与加载未验证。`wandb` 字段由 Hydra launcher 注入，静态核对已通过；仍需实机环境验证。
- 目前没有 G0 训练日志、Checkpoint、独立评测、GPU 小时或成本，故 G0 状态为 `BLOCKED — PRETRAINING`，不是研究复现完成。
